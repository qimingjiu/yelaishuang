# 古风RP网站 · 前期调研笔记

> 调研时间：2026-08。用途：建站前的资料储备与产品决策依据。
> 四路并行调研合并而成：①语C圈生态 ②国内外RP/AI平台 ③人设卡格式体系 ④内置工具清单。

---

## 一、核心结论（先看这个）

1. **古风是语C的"祖奶奶"题材**——语C 2004年起源于贴吧，最早的圈子就是宫斗圈。古风圈至今是审核最严、文笔要求最高、规矩最重的圈子，核心审美指标是"**气**"（角色还原度）。
2. **主阵地至今仍是QQ群+贴吧**，痛点明确：戏文无沉淀、管理纯人肉、审核靠小窗尬聊、招募效率低。没有人把这些做透过。
3. **专门做语C的产品几乎全死了**（语戏、闪聊、Action等），唯一活下来的名人朋友圈靠"去硬核化做低门槛社交"，但被核心玩家唾弃，且曾因版权问题被下架。
4. **AI平台正在分流轻量用户**（星野月活664万、猫箱537万、筑梦岛），但真人共创的不可预知性、考核荣誉感、社交羁绊是AI替代不了的——这正是真人古风RP网站的窗口。
5. **筑梦岛的"梦境"体系最值得整体对标**：剧情存档可保存、可公开、可被他人"接着聊"，直接对应语C的戏文传统。
6. **人设卡有两个体系必须兼容**：语C传统卡（表单字段、小传、戏风雷点）+ AI角色卡V2规范（行业事实标准，PNG嵌JSON，可跨平台互通）。
7. **古风写作=高频查资料**。诗词格律、称谓官职、时辰礼仪都要跳出平台去搜韵/汉典查——"写作时不离开页面"是最大的差异化机会。

## 二、语C生态速览

### 2.1 是什么

语C（语言Cosplay）：纯文字角色扮演，以对戏/自戏/群戏推进剧情。玩家以14–25岁女性为绝对主体。两大初衷：演绎（创作）+ 交友（拟亲属关系社交）。

### 2.2 玩法形态

| 玩法 | 说明 |
|---|---|
| 对戏 | 两人以上按角色言行互动，互相称"对皮"，最核心玩法 |
| 自戏 | 一人完成一段戏，类似第一人称小说 |
| 群戏/联戏 | 多人互动；联戏=约定时间同话题发戏 |
| 句戏/水戏 | 无戏梗的角色身份闲聊，随开随停 |
| 剧场戏 | 有戏梗（背景设定）围绕梗演绎 |
| 水聊 | 皮下（本人）聊天，在水群/水区进行 |

### 2.3 核心术语表（产品设计文案可直接用圈内词）

**身份类**：皮（扮演的角色）、皮上/皮下（角色行为/本人行为）、上皮/入戏、本体/b（句尾加b=皮下发言）、圈名、气/皮气（角色还原度，古风核心审美）、对皮、弧（暂离，"弧半小时"）、纯白/小白/爷白（新人分级，古风群"不拒小白拒爷白"）、玛丽苏/苏。

**行为类**：戏/戏文/码戏、磨皮、开戏/接戏、拉线（分界线，线下禁插戏）、插戏/控戏（控戏=操纵他人角色，最大禁忌）、梗/出梗、甩记录/戏录（入群考核用的历史戏文）、囤戏、复健、句打/短打（vs 屏戏长段）、代餐、818（挂人爆料）、ANW（换世界观开新戏）。

**评价类**：崩皮/OOC、国际三禁（现指白、娘、苏）、堆词（堆砌辞藻不顾句法，古风大忌）、句控/段控/屏控/掌控（1-3行/4-10行/满屏/700字+，字数鄙视链）、戏风四流派（场景派/剧情派/心理派/动作派）。

**格式类**：套/带套（【】等成对符号，套内写动作神态心理、套外写台词）、戏头（开头#号说明）、群名片格式。

**组织类**：审核/考核、考官/陪审（投票如"3p2u"）、前台戏群/后台水群、固设/自拟/皮表/小传、戏录滤白（招募条件）、家族、化妆师（专职NPC接戏推动剧情）、涉三（涉及三次元信息，圈内排斥）。

### 2.4 用户痛点（=产品机会）

1. 同好难找是命门，招募靠贴吧/频道发宣贴，转化低，群越来越短命。
2. QQ群戏文无沉淀：被聊天流冲走、换机炸号即丢、无检索无整理，想让外界看到只能转贴吧，链路冗长。
3. 管理全靠人肉：审核要考官陪聊对戏、群规执行靠盯屏、爆群骂战靠人工。
4. 新人门槛：黑话壁垒+禁白文化，新人"怕被踢不敢说话"。
5. 盗戏/洗戏猖獗，圈内无著作权概念，只能"818"撕逼解决。
6. 低龄+匿名带来的内容合规风险（R-18、沉迷），是所有此类产品的生死线。

## 三、现有平台形态与成败案例

### 3.1 中文语C平台

| 平台 | 形态 | 现状 |
|---|---|---|
| 贴吧 | 楼层接戏+招募贴 | 发源地，至今是招募主渠道；平台衰落、节奏慢 |
| QQ群 | 即时聊天对戏，审核群/戏群/水群三群制 | 绝对主阵地；戏文无沉淀 |
| 腾讯频道 | 帖子流+结构化招募单 | 新兴聚集地 |
| 名人朋友圈 | 朋友圈式+专区剧场+皮编号+心动匹配+戒指CP+圈币 | 唯一穿越周期者（2016年千万融资、2017年200万用户）；但被核心圈唾弃"抹去了语C最基础的东西"，曾因版权下架 |
| 戏鲸/克拉克拉 | 语音pia戏 | 声音演绎分支，非文字主场 |
| 一罐/递爪 | 匿名社交/语音局 | 均已沉寂（变现难、治理成本高） |
| AI平台（星野/猫箱/筑梦岛） | AI角色对话 | 正在分流轻量用户 |

**失败规律**：垂直工具死于天花板+变现难；社交化低门槛者活但丢了核心圈。"戏文沉淀/审核/招募"老三件没人做透。

### 3.2 AI RP平台功能精华（值得抄的）

**SillyTavern（开源标杆，功能全集参考）**：提示词管理器、世界书（关键词触发+二级筛选+递归激活+包含组随机+触发概率+sticky/cooldown时效+token预算+向量检索）、四层lorebook绑定（全局/角色/Persona/聊天）、正则输出清洗、群聊代发、Swipe重说/Continue续写/Impersonate代写、分支聊天、表情差分图、扩展系统。教训：功能全≠好用，新手面对驾驶舱无从下手——必须做渐进式披露。

**筑梦岛（阅文，最值得整体对标）**：
- 角色=梦中人，聊天=入梦，创建=造梦
- **保存梦境**：勾选对话存档，公开后他人可"进入梦境"接着这段剧情聊——剧情接龙/共享存档，把优质剧情变成可复用资产
- **小剧场**：一个角色挂多个场景/番外"副本"
- **身份卡牌**：编辑"你"的身份入局，设羁绊
- 重新入梦（软重置）、"Ta称呼我"+私设层、亲密值系统（规则公开透明）

**星野（MiniMax）**：三层角色创建（形象AI生成18选1/人设五维+few-shot示例对话/音色混合）；对话控制六件套（重说4选1、任意节点回溯、记忆设定、重启、评价、**事件簿**=可编辑的自动阶段摘要）；星念=剧情纪念卡可收藏可交易（创作者抽成2%）。教训：免费额度卡太紧造成"体验断崖"、抽卡与情感陪伴气质冲突。

**猫箱（字节）**：抖音式滑动发现、任意节点回溯"不怕聊崩"、300+创作模板、AI辅助把聊天记录扩写成可发布故事、分步引导式创建（渐进式披露的优秀案例）。

**Character.AI**：极低门槛、Persona跨聊天持久化；教训——审核政策朝令夕改+换弱模型=口碑崩塌前二原因。

**JanitorAI**：结构化角色创建字段（JSON personality+scenario+示例对话+lorebook=行业事实标准组合）、BYOK；教训——基础设施不稳（78%在线率）、NSFW政策突变（突袭实名认证）是用户流失头号原因。

**Chub.ai**：60万+卡库，"卡=内容容器"（一张卡可打包角色+场景+世界+剧情）、精细标签分类、与所有工具互通；教训——社区强产品弱会被"搬空"（用户来进货去别处聊）。

**AI Dungeon**：Do/Say/Story/See四种输入模式、**输出可编辑**（AI当合著者）、Author's Note深度注入文风控制。

**NovelAI**：lorebook机制的发明者；面向"作者"而非"玩家"。

**彩云小梦**：世界设定作为一等公民文档、后悔药分支回溯、世界广场。

### 3.3 英文Play-by-Post论坛

子版块=独立剧本房间；**内置骰子是刚需**（SMF有[dice] BBCode mod）；角色卡外挂Google Sheets；whisper（指定观众可见楼层）是刚需。教训：通用论坛软件开箱即用不了，回合/楼层/可见性要原生设计。

### 3.4 功能共性总结（优秀RP产品的checklist）

- **对话操控层**（标配，缺一即被吐槽）：重说多版本、任意节点回溯+分支、继续生成/代写、消息级编辑删除插入、输出可编辑、正则输出清洗
- **长期记忆层**：自动摘要+用户可编辑事件簿、关键词触发世界书、Persona持久化
- **角色与世界观层**：结构化角色卡（V2行业标准，务必支持导入导出）、角色下的副本层（小剧场）、世界设定一等公民、剧情树可视化
- **社区共创层**：角色/剧情市场+创作者分成、**剧情存档可被他人接着聊**、标签过滤+信息流双发现机制、规则公开的游戏化数值、群聊多角色、二创闭环
- **门槛**：渐进式披露（5分钟出第一个角色）、few-shot示例教学文风
- **合规**：审核与分级策略上线第一天就写死并公开；政策反复是头号信任杀手

## 四、人设卡体系

### 4.1 语C传统人设卡字段（五层结构）

**A. 辨识信息**：姓名（名/字/号）、昵称代号、性别、年龄、生日、身高体重、身份职业、性取向、MBTI
**B. 外貌栏**：体型五官、发色瞳色、特征标记（疤/痣/酒窝）、常用衣着服设
**C. 内在栏**：性格（外在/内在双层写法流行，如"表面清冷自持，绵里藏针"）、优缺点（**必写缺点，这是防苏的关键**）、阴影、价值观、恐惧、梦想、喜恶、习惯小动作、口头禅声线（"嗓音低哑，尾音带笑"）、代表色/代表物/动物塑
**D. 经历栏**：身世家世、背景小传、能力技能、人际关系
**E. 对戏信息栏（语C特有）**：戏风说明（白描/华丽/意识流；日常向/剧情流）、对戏要求（字数下限、弧长、雷点、CP取向、是否接受车戏）、戏录（过往戏文片段作笔力证明）

### 4.2 古风机设特化字段

**宫斗固设卡（真实模板）**：姓名／位分／年龄／家世（品级+嫡庶，如"三品刑部侍郎嫡女"）／容貌／住所／党羽／派别／性格／权力／帝宠（55%）／才艺（医理85%·诗书70%）／掌事宫女／贴身宫女／子嗣／交好／晋升路／人物偏向／考核内容。
→ 特色：**数值化属性**（帝宠%、才艺%）+ 身份政治字段 + 晋升路径 + 百字**小传**（宫斗卡核心审美点，几十字写出戏剧张力）。

**江湖向**：门派、师承、兵器谱、武功路数、江湖称号、恩怨录。
**修仙向**：灵根、境界（炼气→筑基→金丹→元婴→化神）、功法、法器、寿元、心魔。

**容貌描写范式**：诗词式（眉如远山、题判词/定场诗）／白描式（圈内推崇，只写可见细节，忌"倾国倾城"空洞形容词）／数值化。

### 4.3 考核卡 vs 日常卡

- 考核卡=简历：皮上表观特征齐全+附审核戏/戏录，重简洁完整
- 日常卡=长期养的血肉：口头禅小动作人际网随剧情持续更新，固设可写编年史（妃史）
- 字数惯例：戏文按"控"分档；对戏常约定下限（三行起/五十字起）
- 好卡标准：白描外貌、性格有矛盾层次、经历有因果链、明确缺点与雷点标注；苏=完美无缺无代价

### 4.4 AI角色卡 V2 规范（行业事实标准）

顶层信封 `spec: 'chara_card_v2'` + `data` 包裹。字段：

| 字段 | 用途 |
|---|---|
| name | 角色名，同时是 {{char}} 宏展开值 |
| description | 主定义，**永久token**每条注入，越靠底部权重越高 |
| personality | 性格摘要，永久token |
| scenario | 情境，永久token，只放"永久为真"的设定 |
| first_mes | 首条开场白，临时token；**模型从这里学的风格/长度最多**，想回多长写多长 |
| mes_example | 示例对话，`<START>`分隔，临时token；锁声线防漂移；至少含一次拒绝/冷场；必须手写不能粘AI生成 |
| creator_notes | 不进提示词，面向用户展示（POV声明、内容注记、立绘出处、版本号） |
| system_prompt | 非空时替换全局系统提示，须支持{{original}}占位符 |
| post_history_instructions | 替换全局UJB，同上 |
| alternate_greetings | 多开场白数组，前端提供swipe切换 |
| character_book | 角色专属lorebook，角色书优先于全局书 |
| tags / creator / character_version | 不进提示词，仅展示/排序/筛选 |
| extensions | 必须命名空间化，导入导出严禁销毁未知键 |

兼容性惯例：顶层同时复制一份V1扁平字段做垫片。**V2 PNG仍是分发标准**（V3=CharX容器=ZIP，RisuAI主推）。

### 4.5 PNG嵌入原理

JSON→base64→写入PNG的tEXt chunk（keyword=`chara`）；大卡用zTXt压缩chunk（2MB上限）。立绘即卡，分享图=分享角色——与语C圈"发设卡图"传统完美兼容。

### 4.6 Lorebook/世界书机制（SillyTavern全集）

条目字段：keys（支持正则，key本身不进提示词）、content（必须自包含）、enabled、insertion_order（小=靠前）、priority（预算耗尽时小先丢）、selective+secondary_keys（AND逻辑）、constant（恒注入）、position（before_char/after_char）。
ST扩展：9档插入位置（含@D深度注入）、触发策略（恒触发/关键词/向量语义）、概率触发、包含组（同组同时触发按权重抽一条→可做随机事件）、时效（sticky/cooldown/delay）、角色过滤器。
**重要：whole-word匹配对中文必须关闭。**
四层绑定：全局/角色/Persona/聊天，可设合并策略。

### 4.7 好卡写法（实测数据，来自Chub前30星SFW卡采样）

- 67%用纯散文段落，0张用严格PList/W++（W++已淘汰）；赢家是**混合式**：分主题标签段+完整句子，人格经历必须散文（模型需要因果链），可枚举事实（衣着装备技能）才用列表
- 永久token目标800–1500，**2000是红线**；样本中位1085
- first_mes中位178.5词，主流150–350；70%星号动作体/30%纯小说体；中文圈的美化面板在英文头部卡出现率为0
- 70%带mes_example；greeting多数不以提问收尾，主流是"社交压力动作"（角色做出你无法不回应的举动）
- **铁律：不代写{{user}}的行为**（约束要写进system_prompt且用正面措辞）
- lorebook内嵌仅20%，动机是**条件揭示**（秘密按名字/话题分层释放）而非省token

### 4.8 对编辑器设计的启示

1. **双视图同一数据**：表单视图（语C习惯）⇄ 纯文本视图（AI卡习惯）
2. **内置古风模板包**：宫斗固设、江湖、修仙三套（含数值属性、位分/灵根枚举、小传字数引导）
3. **导入导出**：V2 PNG + 裸JSON + V1垫片；lorebook编辑器支持selective/constant/position/概率/递归——这是酒馆用户迁移的硬门槛
4. **好卡检查器**：永久token计数红线、mes_example格式检测、是否代写用户行为、scenario是否永久为真、动词重复检测

## 五、内置工具清单

### 5.1 通用RP工具

**骰子系统**：兼容骰娘指令语法（`.r`/`.rd`/`.ra 侦查`/`.r 3d6+6`/`.rh`暗骰/`.st`存属性/`.jrrp`今日人品），服务端掷骰留痕防截图造假，暗骰GM可见，与角色卡数值联动判定，自定义规则模板。圈内零学习成本是硬要求。

**剧情/时间管理**：戏录自动归档（按场景→回合成卷，可回看导出txt/PDF）、剧情线看板（主线/支线树，标记进行中/完结/坑）、**双时间轴**（戏内纪年"X年X月辰时"与现实时间并行——古风剧情跨数月，没这个新人补档极痛苦）、前情提要为每卷开头摘要位。

**多人对戏组织**：戏楼分层（主楼纯戏文禁水+水楼皮下讨论自动关联，对应前台/后台）、回合看板（显示当前轮到谁，接戏后自动流转+@下一位）、弧/暂离标记（可视化谁欠戏，替代人肉拉线催戏）、报名审核流在线化、围观只读权限+有规矩的插戏申请。

**资料工具**：人设卡模板库（一张卡多场景投递，审核直接调卡）、世界观设定集（词条化+标签，开戏时钉侧栏防崩设定）、关系图谱（CP/师徒/宿敌/血缘，新人一键看懂阵营）。

**随机工具**：古风取名（人名/法号/地名/门派/武功/法宝，出典可溯）、自定义转盘抽签、随机事件表（跑团式d100表："赶路奇遇表""宫中偶遇表"）、今日运势娱乐功能。

### 5.2 古风特化工具（差异化重点）

圈内人现在写古风戏要反复切出去用：搜韵（90万首诗词+格律校验，中科院背书）、汉典（字义字源古音）、ctext（50亿字古籍检索）、古诗文网、各类竖排繁简小工具。**内置原则：写作时不离开页面。**

**写作辅助**：
- 编辑器侧边"写诗助手"：选词牌→填词→实时平仄/押韵标注（平水韵/词林正韵）
- 用典/诗词检索面板：按意象（梅、雪、孤舟）检索例句，一键引用进戏文自动标注出处
- 一键繁简转换、戏文竖排预览/导出古书排版PDF（"戏录成书"）
- 古风排版主题：楷体/宋刻本字体、信笺纸纹、印章落款

**古代知识速查**（结构化"古风百科"卡片库，每条=名称+朝代+释义+使用场景+例句，按朝代筛选，标注通用/专用）：
- 称谓：谦敬体系（家/舍/先/小 vs 令/尊/贤；陛下/妾/下官）——编辑器内选中词右键弹出正确用法（如"妾在宫斗戏中对皇上不可用"）
- 官职：九品十八阶、三省六部，各朝差异
- 礼仪流程生成器：选"及笄/大婚六礼/上朝"→输出步骤清单，主持人照着带戏
- 时辰换算器：现代时间→"酉时三刻/一更天"，可插入戏文时间戳
- 节日黄历面板：戏内日历标注传统节日，可做全站活动

**江湖/仙侠向**：境界体系模板库（经典修仙流/洪荒流/武侠品级，可自定义层级+突破条件，与角色卡联动显示当前境界）、门派系统页（宗旨/掌门/弟子名录/武学库/议事厅演武场子戏楼——门派是古风群戏的长期组织单元）、武功招式生成器+自建武学库、悬赏/通缉榜（世界事件板）。

**宫廷向**：位份模板（唐制/宋制/清制/通用宫斗制预置，可自定义）、全站位份表公示、升贬记录入时间轴（"某年某月晋封昭仪"档案——宫斗核心爽点）、东西六宫可视化入住图、请安/翻牌子等日常流程玩法化。

### 5.3 平台基础功能

- **多马甲**：一账号N张皮，各带头像/人设卡/独立时间线，发帖选皮，皮上/皮下消息视觉分隔（对应带套文化）

## 七、红线与教训（前人尸体）

1. **别学语戏只做工具没社交**——垂直工具死于天花板；也别学名朋为下沉牺牲核心圈规矩（解法：专区隔离，硬核群与轻玩法分区运营）。
2. **审核/合规策略上线第一天写死并公开**：Glow下架、名朋版权下架、JanitorAI突袭实名认证、星野静默关功能——政策反复是头号信任杀手。分龄+分级+举报比一刀切更符合社区现实。
3. **经济系统控制铸币权**：Gaia Online死于通胀；星野抽卡被吐槽"情感陪伴变味"。
4. **基础设施要稳**：JanitorAI 78%在线率是口碑崩塌前二原因之一。
5. **圈内对AI文有排斥情绪**：AI功能定位应是"陪练/润色/化妆师NPC"，不可替代真人对戏的核心地位。
6. **冷启动切入点**："帮群主把审核和戏录搬进网站"——古风群招募仍集中在贴吧/频道/B站。

## 九、产品形态决策（2026-08，妁妁拍板）

**做工具，不做平台。** AI RP 客户端，真人RP不在范围内，无中心服务器（MVP阶段）：

- **形态**：纯客户端开源软件，BYOK（用户自带模型API），聊天与人设卡数据全部存用户本地。网站只提供功能与内置工具。
- **分发**：GitHub Releases 桌面安装包（Tauri 套壳）+ GitHub Pages 网页版（PWA，浏览器可直接安装）。一份代码两种形态；不做"网页转应用"工具。
- **合规逻辑**：服务器不碰用户内容 → 内容平台审核义务整体消失，身份变为开源软件作者，适用 GitHub 条款。私密生成内容归用户与其模型服务商之间的协议（OpenAI/Anthropic 各有 usage policy）。
- **社区约定**：写在仓库（CODE_OF_CONDUCT.md），约束范围=仓库社区言行 + 官方随附内容（示例卡/模板保持全年龄，release 页面带年龄提示）。不约束、也无法约束私密使用。
- **卡生态**：不做官方卡库。编辑器原生支持 chara_card_v2 导入导出（含 PNG tEXt 嵌入），借力 Chub 等既有卡站生态。
- **已知技术坑**：浏览器直连模型 API 的 CORS 限制——Tauri 层转发解决桌面端，网页版需内置可选本地代理。
- **范围修订**：本笔记中"真人语C社区"相关功能（审核流、戏楼、招募板等）不再适用；AI RP 侧的世界书/角色卡/对话控制/古风工具仍为有效需求。NSFW 管制框架降级为"仓库与官方内容自律"，平台级管制框架保留备用。
- **未来决策点**：若日后要加官方卡库/戏录广场/云同步，平台义务整体回归，届时启用"公开区严格SFW + 私密本地自理"框架。
