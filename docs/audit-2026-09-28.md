# 代码审计报告 · 2026-09-28

> 范围：全部前端源码（`src/`）、桌面壳（`src-tauri/`）、工具脚本（`tools/`）、CI（`.github/workflows/`）、构建配置。
> 基线：`npm run build`（tsc + vite）通过；正文所引行号以当时工作区为准。

## 一、Bug（按严重程度排序）

### B1 · 高：**「重说」先删原楼层再发请求，请求失败时原回复永久丢失**

位置：`src/pages/Chat.tsx:448-453`（`generate()` 的 `dropLastAssistant` 分支）

```ts
const floors = dropLastAssistant ? latest.floors.filter(...) : latest.floors;
if (dropLastAssistant && floors.length !== latest.floors.length) {
  updateStory(storyId, { floors });   // ← 在发请求之前就持久化删除
}
```

点「重说」会先把最后一条 AI 楼层**写入 localStorage 删除**，然后才发起请求。如果此时撞上 401 / 断网 / 超时，`catch` 只设置错误提示——原楼层已经没了，无法恢复。这是真实的数据丢失路径，而且触发条件（Key 失效、网络抖动）很日常。

**修复**：楼层删除只保留在内存里（用于 `buildMessages`），请求成功拿到新文本后连同新楼层一次性写入；失败/空结果时原楼层原封不动。

### B2 · 高：**mock-llm 按字节切割产生乱码，「冒烟测试」测的是坏数据**

位置：`tools/mock-llm.mjs:46-59`

```js
const piece = bytes.subarray(cuts[i], cuts[i + 1]);
res.write(`data: ${JSON.stringify({ ... content: piece.toString('utf8') } ...})`);
```

`cuts = [0, 9, 17, 40, ...]` 会落在汉字的 UTF-8 字节中间；`Buffer.subarray(...).toString('utf8')` 对不完整的多字节序列输出 **U+FFFD 替换符**（已实测：`"檐角"` 后跟 `�`）。也就是说损坏发生在 mock 内部，前端收到的文本本身就带乱码——注释声称「验证前端跨 chunk 的 UTF-8/SSE 解析」，实际上前端根本没有机会行使 `TextDecoder({ stream: true })` 的缓冲职责，而且每次 mock 回复都必然夹带 `�`，会污染人工联调时的观感判断。

**修复**：把完整的 SSE 帧（含 `data:` 前缀与换行）整体编码成字节后再按字节切割下发——切点穿过事件边界也由前端按行重组，跨 chunk 的不完整字节由 `TextDecoder(stream:true)` 正确缓冲。

### B3 · 中：**桌面端流式请求非 200 时，上游错误详情被吞掉**

位置：`src-tauri/src/lib.rs:86-141` + `src/lib/llm.ts:179`

Rust 侧非 2xx 依然进入流式循环，上游错误 JSON（如配额不足、内容审核拒绝的具体原因）被当作 delta 发出；前端的 `SseExtractor` 只认 `data:` 行，将其丢弃。最终 `readStatus({ status, body: '' })` 只能报出：

```
HTTP 401：API Key 无效或未授权 —— （无响应体）
```

用户看不到服务商返回的具体原因，排障只能抓包。

**修复**：Rust 侧非 2xx 时直接读取完整 body，经新增的 `StreamEvent::HttpError { status, body }` 事件回传；前端 `readStatus` 用它展示真实错误体。

### B4 · 中：**删光角色与身份后刷新页面，内置内容包整体复活**

位置：`src/lib/store.ts:188-220`（`ensureSeeded`）

播种条件是「当前库为空」（`characters.length === 0 && personas.length === 0`）。用户把内置内容清空（这是「本地优先」应用应有的自由）后一刷新，8 张角色卡 + 世界书 + 身份全部回来，无法真正清空库。

**修复**：播种改为「每台设备只做一次」——以 `yfs.seeded.v1` 标志为准；老用户（有数据、无标志）跳过播种并补写标志。

### B5 · 中：**跨戏楼并发时，发送静默失效（消息发出去了，永远没有回复）**

位置：`src/pages/Chat.tsx:430-431`（`generate` 开头 `if (streamRef.current) return;`）与 `onSend`（496-512）

`streamRef` 是全局单例：A 戏楼正在流式时，切到 B 戏楼点「发送」，`onSend` 会先把用户楼层 append 进存档，然后 `generate()` 因为 `streamRef.current` 非空**静默 return**——用户消息已入库，但没有 AI 回复、没有错误提示、没有按钮反馈，看起来像「卡住了」。

**修复**：`onSend` / `generate` / `onContinue` 在检测到全局流式进行中时显式报错提示（「另一座戏楼正在生成中」）。

### B6 · 中：**「内置卡修改另存为你的副本」文案与实际行为不符——实际是原地覆盖**

位置：`src/pages/Workshop.tsx:41-45`（`CharacterEditor.save`）与文案（59 行）

编辑随仓库分发的内置卡时，保存用的是原 `id`（`upsertCharacter` 按 id 覆盖），且 `builtin: true` 原样保留——**直接覆盖了内置卡，原内容无法恢复**，与界面承诺「修改将另存为你的副本」相反。

**修复**：编辑内置卡保存时生成新 id、置 `builtin: false`（真正的副本），原卡保留。

### B7 · 低：**世界书导入失败也显示绿色「成功」样式**

位置：`src/pages/Workshop.tsx:478`

```tsx
{error && <p className="ok">{error}</p>}
```

`WorldbooksTab` 的 `error` state 既装成功信息也装失败信息，但永远套用 `ok` 样式——导入失败用户看到的是绿色「导入失败：…」。

**修复**：按内容区分 `ok` / `error`。

### B8 · 低：**角色卡被删除后，「让 AI 更新摘要」抛原始 TypeError**

位置：`src/pages/Chat.tsx:214`（`SidePanel.aiSummarize` 使用 `character!`）

戏楼绑定的角色卡被删除后，`character` 为 `undefined`，`buildMessages` 读 `character.systemPrompt` 抛 `Cannot read properties of undefined`，错误面板显示原始异常文本。`generate()` 对此有友好提示（441 行），摘要功能没有。

**修复**：与 `generate()` 一致的友好报错。

### B9 · 低：**网页端本地代理不支持流式转发——对戏的逐字流式体验完全丧失**

位置：`tools/local-proxy.mjs:86`

```js
res.end(Buffer.from(await upstream.arrayBuffer()));
```

代理把上游响应**全量缓冲**后才一次性返回。README 主打「网页端直连撞墙时用本地代理对戏」，但走代理时没有任何流式效果（整段等完才出现），SSE 的意义被抹掉。

**修复**：逐块 pipe 到客户端响应；上游中断时销毁连接。

### B10 · 低：**Rust 每次请求新建 `reqwest::Client`，且无连接超时**

位置：`src-tauri/src/lib.rs:45`（`build_request` 内 `Client::new()`）

每个请求（含每轮对戏、每次测试连接）都新建客户端：连接池无法复用，每次重做 TCP + TLS 握手；也没有连接超时，上游 DNS/连接挂起时请求无限等。

**修复**：`OnceLock` 全局共享 `Client`，设 15s 连接超时（读不设总超时，流式回复天然长）。

### B11 · 低：**流式「停止」按钮在上游挂起时可能无效**

位置：`src-tauri/src/lib.rs:98-117`

Rust 转发循环的取消检查在 `stream.next().await` **之前**——如果上游发出响应头后长时间不再吐 chunk，`next()` 一直阻塞，取消标志要等到下一个 chunk 才被发现。「停止」按钮点了没反应。

**修复**：用 `tokio::select!` 让取消轮询（250ms）与读 chunk 并行竞争。⚠️ 本机无 Rust 工具链，此改动无法本地 `cargo check`，发版前请先跑一次桌面 CI 验证（其余 Rust 改动 B3/B10 不含新依赖与新语法原语，风险很低）。

## 三、记录在案、暂不动代码（后续版本）

1. **无 token 预算控制**：`buildMessages` 按楼层数（默认 40 层）截取，世界书恒注入 + 记忆簿 + 摘要叠加后没有总 token 预算，长篇戏楼可能超模型窗口（P1 规划里的向量检索/摘要自动化是正解）。
2. **localStorage 容量上限（约 5MB）**：全部戏楼明文 JSON 单 key 存储，长年累月的戏录可能触顶。中期应迁 IndexedDB，`persist()` 已有 catch 兜底。
3. **API Key 明文存 localStorage**：BYOK 客户端的常规做法，PWA 下没有更安全的可选 API；桌面端可考虑 OS keyring（Tauri plugin）。
4. **流式期间整页重渲染**：每个 delta 触发 `Chat` 全树 re-render，楼层多时可能卡顿。可在 P1 把流式楼层拆为独立订阅组件或做楼层虚拟化。
5. **CI `macos-13`（Intel）runner**：GitHub 已公告 macos-13 淘汰计划，Intel DMG 构建可能在未来失效，届时改 `macos-latest` + 交叉编译或放弃 Intel 包。
6. **`SseExtractor` 不合并一个事件内的多 `data:` 行**：OpenAI 兼容流均为单行 `data:`，规范允许的多行合并场景目前不存在，保持现状。
